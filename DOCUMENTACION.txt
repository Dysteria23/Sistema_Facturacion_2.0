FARMACIA PÉREZ — SISTEMA DE FACTURACIÓN


1. QUÉ ES ESTE PAQUETE
------------------------
Sistema de punto de venta multi-tenant  para farmacias,
en Flask + SQLite. Cada empresa (tenant) tiene su propio login, catálogo
de productos, historial de ventas y usuarios, aislados por la columna
empresa_id en cada tabla.

Módulos:
  app.py                  Rutas HTTP, sesión (Flask-Login), CSRF.
  auth.py                 Hash y verificación de contraseñas (werkzeug).
  database.py             Esquema SQLite y creación/semilla inicial.
  logic.py                TODA la lógica de negocio (ver sección 2).
  migrate_to_multitenant.py  Migración de una base single-tenant vieja.
  templates/*.html        7 plantillas Jinja2.
  static/css/styles.css   Estilos (dirección "botica": verde pino +
                           papel + ámbar, precios en monoespaciado).
  static/js/app.js        Carrito, modales, tema oscuro, cierre de caja.

Si tu logic.py ORIGINAL tenía reglas de negocio que no son deducibles

reconstrucción NO las tiene — no existía forma de adivinarlas sin

en vez de fabricarlo. Compara esta versión contra tu original (si lo
recuperas) antes de usarla con datos reales de clientes.

Reglas de negocio implementadas en esta reconstrucción:
  - Venta: transacción atómica (BEGIN IMMEDIATE): o se descuenta todo
    el stock y se registran todas las líneas, o no se toca nada.
  - Venta: líneas repetidas del mismo producto en un carrito se
    combinan antes de validar stock.
  - Venta: rechaza carrito vacío, cantidades ≤0, productos inexistentes
    o de otro tenant, y stock insuficiente (con VentaError legible).
  - Producto duplicado por nombre: suma el stock en vez de duplicar
    (coincide con el aviso ya visible en inventario.html).
  - Eliminar producto / usuario: desactivación lógica (activo=0), no
    borrado físico — porque ventas.producto_id referencia productos y
    un DELETE real rompería el historial de ventas ya facturadas.
  - No se puede desactivar al último administrador activo de una
    empresa (evita quedarte sin acceso de admin).
  - Reportes: diario / semanal (7 días) / mensual (desde el 1°) /
    anual (desde el 1 de enero), todo filtrado por empresa_id.
  - low_stock_products: umbral ≤10 unidades (coincide con "Bajo" +
    "Crítico" en inventario.html).

4. CÓMO CORRERLA
-------------------
  1. python3 -m venv venv && source venv/bin/activate  (o venv\Scripts\activate en Windows)
  2. pip install -r requirements.txt
  3. export FLASK_SECRET="algo-largo-y-aleatorio"   (Windows: set FLASK_SECRET=...)
  4. python app.py
  5. Abre http://localhost:5001 — entra con: empresa "demo", usuario
     "admin", contraseña "cambiar123" (cámbiala de inmediato).

Para producción define además FLASK_ENV=production — app.py se niega a
arrancar en producción sin FLASK_SECRET definido (ya lo tenía así tu
código original, lo dejé intacto).
